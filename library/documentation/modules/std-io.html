Overview

How to read this reference

Green public labels mark accessible declarations; amber private labels mark implementation details. A public type can contain private fields. Visibility is shown for each member independently.

Read fields as value.field and call methods as value.method(), including zero-argument methods. Required methods describe a type's contract; functions and methods list implementations. Overloads share one navigation entry, with a signature and description for each overload.

Signatures show resolved types and effects, including inferred information, and are reference notation rather than copyable declarations. consume transfers ownership: pass an existing owned binding with move. read, mut, and reshape describe access to the named group or path; suspend permits suspension. Check the description for bounds, units, copying, and failure behavior.

Option<T> represents an optional value; Result<T, E> carries success or a typed error. Assertions and execution failures are distinct from returned errors.

Binary and text stream contracts with complete-transfer helpers.

Readers report EOF with an empty value. Writers may make partial progress. read_all, write_all, and copy propagate the first error without rolling back earlier I/O. write_all and copy flush on success. Implementations must honor the progress requirements in Reader and Writer to avoid nonterminating retries. Use Reader or Writer when only one direction is needed and Duplex for both. Resource replacement belongs to std.resource.Writable rather than stream Writer. Flushing makes output visible to the destination; it does not promise durable storage. Use Stdin.new() for blocking command-line input, including redirected files and pipes. Adapters share the invocation's input stream; reads advance it and never close it.

Timed readiness for reading or accepting. Zero polls without waiting; negative timeouts fail. True includes EOF and pending I/O errors. Readiness is advisory when consumers race.

Readerpublic

A stateful source of binary data.

read returns at most maximum bytes. Empty bytes indicate clean end-of-stream. A successful read of a non-empty stream must return at least one byte.

Required methods

  • read
    Reads at most `maximum` bytes; callers supply a positive maximum. For that positive request, empty bytes mean EOF and a nonempty result means progress.

Writerpublic

A stateful destination for binary data.

Required methods

Stdin.readfunctionpublic

pub func read(self: Stdin, maximum: Int) -> Result<Bytes, IoError> [mut self]

Reads at most maximum bytes, blocking until input, EOF, or an error. maximum must be in 1..1048576 inclusive; invalid requests return IoError. Empty bytes mean EOF. Bytes consumed before a subsequent error are not restored.

Stdin.read_linefunctionpublic

pub func read_line(self: Stdin) -> Result<Option<String>, IoError> [mut self]

Reads one UTF-8 line, removing LF and an immediately preceding CR. Returns Some("") for an empty line and None only at EOF before any bytes. A final unterminated line is returned, preserving a trailing CR. Invalid UTF-8 returns IoError after consuming the line. Reads may block; memory grows with line length. An I/O error discards any partial line already consumed.

copyfunctionpublic

pub func copy<E>(reader: Reader<E>, writer: Writer<E>) -> Result<Int, E> [mut reader, mut writer]

Copies through EOF, flushes the writer, and returns the total byte count. Reads chunks of at most 8192 bytes and retries partial writes. The first read, write, or flush error ends the operation; completed I/O is not rolled back.

read_allfunctionpublic

pub func read_all<E>(reader: Reader<E>) -> Result<Bytes, E> [mut reader]

Reads through EOF and returns all bytes, retaining the reader for further use. Propagates the first read error; already consumed bytes are not restored. Memory use grows with the input size, so the stream must eventually terminate.

write_allfunctionpublic

pub func write_all<E>(writer: Writer<E>, contents: Bytes) -> Result<(), E> [mut writer]

Writes all bytes, retrying partial writes, then flushes once. Empty input still flushes. A write or flush error is returned unchanged; bytes already accepted by the destination are not rolled back.
